# Юлия Лахтина → GitHub → Beget

Готовый исходный проект с автоматической публикацией. Работает на обычном хостинге Beget с PHP 8.2+ и SSH. На сервере не нужны Git, Node.js, npm, Composer или база данных.

## Как проходит обновление

1. Я меняю исходники в этой папке, проверяю их и отправляю commit в ваш репозиторий.
2. Push в `main` запускает GitHub Actions: установка зависимостей, тесты, сборка HTML/CSS/JS, проверка PHP и упаковка.
3. Pipeline подключается к Beget по SSH, загружает сборку, сохраняет резервную копию публичных файлов и публикует изменения.
4. Pipeline проверяет по HTTPS, что сайт отдаёт нужную ревизию. Результат виден во вкладке Actions.

Pull request только проверяет сборку. Вручную повторить публикацию можно через Actions → Build and deploy to Beget → Run workflow → main. До первоначальной настройки автоматическая публикация выключена переменной `BEGET_DEPLOY_ENABLED`.

В этой схеме сервер получает уже собранные файлы из pipeline; команду `git pull` на хостинге выполнять не нужно. Это позволяет использовать обычный PHP-хостинг.

## Что настроить один раз

### Beget

Создайте сайт в панели Beget, привяжите домен, включите SSL, PHP 8.2+ с OpenSSL и SSH-доступ. Запишите абсолютный путь **к папке, внутри которой находится public_html**, например `/home/LOGIN/SITE`. Укажите реальный путь, без `~`, пробелов и символических ссылок. На сервере нужны `bash`, `rsync`, `tar`, `flock`, `realpath` (workflow проверит основные утилиты).

Сгенерируйте отдельный SSH-ключ для GitHub Actions. Публичную часть добавьте в `~/.ssh/authorized_keys` аккаунта Beget. Приватную часть сохраните только в секрете GitHub `BEGET_SSH_KEY`; не отправляйте её в чат и не коммитьте в репозиторий. Для отдельного ключа можно использовать:

```sh
ssh-keygen -t ed25519 -C "github-beget-deploy" -f ./beget_deploy
```

Ключ для безоператорного запуска должен быть без passphrase; хранится как секрет GitHub. Для него в `authorized_keys` можно запретить port/agent/X11 forwarding и PTY. Не задавайте `command=...`, пока не настроен специальный ограниченный командный обработчик: deploy использует bash и rsync.

Получите SSH host key сервера. `ssh-keyscan -p 22 SERVER` помогает получить строку, но **сам по себе не подтверждает её подлинность**: перед сохранением проверьте fingerprint через доверенный канал Beget. Проверка host key в workflow обязательна, `StrictHostKeyChecking=no` не используется.

### GitHub

Создайте репозиторий и загрузите содержимое этой папки в его корень. `.github/workflows/beget.yml` должен попасть в репозиторий. Настройки находятся в Settings → Secrets and variables → Actions.

**Repository secrets:**

| Имя | Значение |
|---|---|
| `BEGET_HOST` | SSH-сервер из панели Beget, без `https://` |
| `BEGET_USER` | SSH-логин |
| `BEGET_SITE_DIR` | Абсолютный путь к папке сайта, родитель `public_html` |
| `BEGET_SSH_KEY` | Полный приватный deploy-ключ, включая BEGIN/END |
| `BEGET_KNOWN_HOSTS` | Проверенная строка known_hosts для этого сервера и порта |

**Repository variables:**

| Имя | Значение |
|---|---|
| `SITE_URL` | `https://psycholog.laht1nka.ru` или фактический основной HTTPS-домен |
| `BEGET_PORT` | `22`, если Beget не указал другой порт |
| `BEGET_DEPLOY_ENABLED` | `true` после заполнения секретов и проверки пути |

Нельзя помещать SMTP-пароль в GitHub variables, public/site-config.js или репозиторий. Для деплоя он вообще не нужен. Для приватного репозитория проверьте доступные минуты GitHub Actions вашего тарифа. Правила защиты ветки `main` настраиваются владельцем репозитория.

## После первой публикации

На Beget появится `private/mail-config.php` рядом с `public_html`. Добавьте туда пароль приложения Яндекс.Почты и установите `enabled => true`. Отправитель и получатель — `psy@lahtinka.ru`. Убедитесь, что `site_url` совпадает с доменом. По умолчанию форма демонстрационная; отправка реальных писем без пароля не проверена.

При обновлениях сохраняются без изменений:

- `private/mail-config.php` — пароль и почтовые настройки;
- `private/storage/` — временные ограничения частоты отправок;
- `public_html/site-config.js` — настроенные идентификаторы аналитики.

Изменения шаблона `public/site-config.js` не перезаписывают настроенный серверный файл: меняйте этот файл на Beget вручную либо отдельно согласуйте его обновление.

Юридические страницы пока являются проектами: перед приёмом реальных заявок заполните реквизиты, обработчиков, сроки хранения и описание антиспам-ограничителя.

## Резервная копия и откат

Каждая публикация сначала сохраняет `public_html` в `.deploy-backups/ДАТА-REVISION.tar.gz` рядом с публичной папкой. Публикации выполняются последовательно; файловая блокировка также защищает от параллельного ручного запуска.

Ресурсы загружаются до HTML, старые файлы с хешами не удаляются, чтобы уже открытые вкладки продолжали работать. Это пофайловое обновление, а не атомарное переключение всех страниц одновременно. При ошибке копирования восстанавливаются публичные файлы из backup; новые файлы могут остаться рядом. Почтовые настройки не изменяются. Если проверка HTTPS после публикации не прошла, Actions сообщит об ошибке; автоматического отката по результату этой внешней проверки нет.

Для ручного отката выберите нужный backup и выполните через SSH из папки сайта:

```sh
tar -xzf .deploy-backups/ИМЯ_РЕЗЕРВНОЙ_КОПИИ.tar.gz -C .
```

Резервные копии, загрузки `.deploy-incoming` и старые ресурсы намеренно не удаляются автоматически. Периодически проверяйте свободное место и удаляйте только уже ненужные сохранённые версии. Текущие настройки почты и статистики не публикуются в Git.

## Работа с исходниками

```sh
corepack enable
pnpm install --frozen-lockfile
pnpm test
pnpm build
pnpm package
```

Готовые файлы: `dist/beget/public_html` и `dist/beget/private`. При ручной установке скопируйте `mail-config.example.php` в `mail-config.php` вне публичной папки. Для просмотра интерфейса используйте `pnpm dev`; PHP-форма требует PHP-сервера, маршрут `/api/booking.php` не обрабатывается Next dev.

Контент — `content/site.js`, оформление — `css/site.css`, PHP — `server/public_html/api/booking.php`. Фотографии уже подготовлены в нескольких размерах. Сканы дипломов, адрес кабинета, ссылки MAX и прочие отсутствующие данные не выдуманы.

## Что ещё нужно для первого реального push/deploy

Этот комплект содержит конфигурацию, но не подключён к вашему серверу: нужны URL репозитория, SSH-сервер, логин и путь, а секреты нужно добавить в GitHub. Публикация на реальный Beget пока не выполнялась. После подключения команда в чате «обнови сайт» будет означать подготовку и push изменений; результат pipeline проверяется отдельно.

Документация: [SSH Beget](https://beget.com/ru/kb/faq/hosting/dostup-k-serveram), [GitHub Actions deployments](https://docs.github.com/en/actions/how-tos/deploy/configure-and-manage-deployments/control-deployments).
